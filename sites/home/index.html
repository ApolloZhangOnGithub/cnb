The problem

Without cnb
session 1 refactors auth module
session 1 ends
session 2 starts
"what auth module? let me look around..."
rewrites the same code differently
session 3 finds conflicts, gives up
With cnb
session 1 refactors auth module
session 1 logs handoff report
session 2 starts, reads the board
"auth is done, tests pass. billing next."
picks up exactly where session 1 left off
session 3 checks board, no conflicts

How it works

A shared board tracks who's working on what. Each AI session checks in, claims tasks, and reports results.

$ cnb board
 
lisa-su notification/* active
forge board db review
sutskever model eval active
tester pytest suite queued
 
4 tongxue · dispatcher heartbeat: 1.2s · pending: 0
$ board --as lisa-su task done
OK task #12 done — tests passed, PR #47 created

Capabilities

Board

Local SQLite keeps messages, tasks, and status — structured, queryable, outside the context window.

Ownership

Each session claims specific modules. New sessions know what they own and what to leave alone.

Handoff

Sessions record what changed, which tests passed, and what's blocked. The next session reads this.

Feishu

Message your AI team from your phone. Quiet until there's a final result.

Local-first

tmux, SQLite, local files. No cloud account. Every piece of state is inspectable.

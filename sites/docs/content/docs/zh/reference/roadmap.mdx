cnb 围绕所有权来组织开发。这不是一份按难度排的功能清单，而是按组织优先级排序的工作方向。

## 当前焦点：角色拆分

现在最重要的一件事是把 lead 角色拆成两个独立角色（[#64](https://github.com/ApolloZhangOnGithub/cnb/issues/64)）：

- **终端主管同学**：按机器分配，面向用户，接收外部消息，汇报状态
- **项目负责同学**：按仓库分配，负责项目级团队管理和交付

这个拆分阻塞了多项所有权、通信和调度决策，是当前路线图的关键路径。

## 所有权体系

所有权是 cnb 的核心，正在分阶段建设：

- **注册与自治**（[#45](https://github.com/ApolloZhangOnGithub/cnb/issues/45)）——核心命令已完成，文档和边缘情况待补
- **交接机制**（[#49](https://github.com/ApolloZhangOnGithub/cnb/issues/49)）——正在开发转移、孤儿检测、离职和兜底方案
- **路由准确性**（[#87](https://github.com/ApolloZhangOnGithub/cnb/issues/87)）——目前路由还很粗放，需要引入置信度和冲突处理
- **自适应扩展**（[#30](https://github.com/ApolloZhangOnGithub/cnb/issues/30)）——等利用率数据积累后再制定规则

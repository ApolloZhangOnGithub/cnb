cnb is local orchestration software. It does not bill per message, per tongxue, or per project. Costs come from the agent engine underneath cnb, plus any external service the agents call.

## What You Pay For

| Layer | Who bills it | Notes |
|-------|--------------|-------|
| cnb package | cnb | No hosted metering. State is local SQLite and files. |
| Claude Code engine | Anthropic | Depends on the Claude Code plan, API setup, or organization billing. |
| Codex engine | OpenAI | Depends on the ChatGPT plan, Codex included usage, extra credits, or API key billing. |
| Local infrastructure | You | tmux, SQLite, local disk, CPU, and network. |
| External services | Their provider | GitHub, CI, cloud runners, SaaS APIs, or any tool called by an agent. |

cnb's narrow claim is that coordination is cheap because messages, tasks, status, and ownership live in shell commands, SQLite, tmux, and files. The underlying model calls are still real usage.

## Cost Model

```text
total usage =
  sum(model usage from active tongxue)
  + model usage from the terminal supervisor tongxue
  + optional cloud/code-review/automation usage
  + small LLM-visible coordination overhead
```

Team size matters. Six active tongxue can consume roughly six streams of model capacity when all are coding. cnb reduces waste by avoiding the pattern where every agent reads every other agent's full transcript.

## What Stays Off-Model

These operations are local and do not create model calls by themselves:

- `cnb board --as <name> inbox`
- `send`, `ack`, `status`, `task`, `pending`, `own`, and `view`
- dispatcher health checks
- SQLite reads/writes
- tmux process inspection
- issue files and local reports stored on disk

They can still become model input later if a tongxue reads or summarizes them.

## Cost Controls

- Keep teams small until ownership boundaries are clear.
- Prefer board commands over asking one tongxue to relay every message.
- Avoid broadcasting long context to every tongxue.
- Use task files, issue files, and ownership maps as durable context.
- Use lower-cost models for low-risk maintenance work.
- Stop idle tongxue instead of leaving them in loops.
- Check the provider's usage dashboard before and after large runs.

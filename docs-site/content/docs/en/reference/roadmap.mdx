Last updated: 2026-05-10

cnb is organized around ownership. The roadmap is ordered by organizational priority, not by implementation difficulty.

## Management Principles

1. Organization structure comes before feature work.
2. Infrastructure needs explicit owners.
3. Research hypotheses and execution backlog are separate.
4. One problem should have one issue.
5. Operational breakage needs an owner and a fix, not a long design debate.

## Top Priority: Role Definition

The lead role is being split into:

- terminal supervisor tongxue: per-machine, user-facing, receives wake-up messages, reports status, and coordinates local projects
- project responsible tongxue: per-repo, owns project-level team management and delivery

This blocks several ownership, communication, and dispatcher decisions. See issue #64.

## Ownership Lifecycle

| Area | Status |
|------|--------|
| Ownership registration and autonomy (#45) | core commands are done; docs, integration tests, and edge cases remain |
| Ownership handoff (#49) | active branch work for transfer, orphan detection, offboarding, and fallback |
| Ownership routing accuracy (#87) | needs routing evidence, confidence, conflict handling, and low-confidence fallback |
| Ownership protection and adaptation (#30) | needs utilization and throughput data before adaptive scaling rules |

Current routing is intentionally described as early: file owner lookup is longest path-prefix matching, issue scan checks ownership patterns in title/body, and CI failure routing is broad.
